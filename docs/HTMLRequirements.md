# Стандарты кодирования для HTML

Эта документация описывает стандарты написания кода на языке HTML, призванные обеспечить единообразие, читаемость, доступность и удобство поддержки кода в проектах.

## 1. Базовые соглашения


### 1.1. Кодировка и DOCTYPE

* Все HTML‑файлы должны использовать кодировку **UTF‑8**.
* В начале каждого документа должен быть объявлен DOCTYPE: `<!DOCTYPE html>`.
* Укажите язык документа через атрибут `lang` в теге `<html>` (например, `lang="ru"` для русского языка).

**Пример:**
```html
<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <title>Пример страницы</title>
</head>
<body>
    <!-- Содержимое страницы -->
</body>
</html>
```

### 1.2. Структура документа

Каждый HTML‑документ должен содержать следующие обязательные элементы:

    <!DOCTYPE html>;

    <html> с атрибутом lang;

    <head> с <meta charset="UTF-8"> и <title>;

    <body>.

## 2. Синтаксис и форматирование
### 2.1. Отступы и пробелы

* Используйте 2 пробела для отступов (не табуляцию).

* Каждый вложенный элемент должен иметь отступ относительно родительского.

* Оставляйте пустые строки между логическими блоками для улучшения читаемости.

Правильно:
```html
<div class="container">
  <h1>Заголовок</h1>
  <p>Текст абзаца.</p>
</div>
```

Неправильно:
```html
<div class="container">
<h1>Заголовок</h1><p>Текст абзаца.</p>
</div>
```

### 2.2. Кавычки и регистр

* Всегда используйте двойные кавычки для значений атрибутов.

* Пишите все теги и атрибуты в нижнем регистре.

Правильно: ```<img src="image.jpg" alt="Описание">```
Неправильно: ```<IMG SRC='image.jpg' ALT='Описание'>```
### 2.3. Закрывающие теги

* Всегда явно закрывайте теги, даже если они могут быть опущены браузером (например, `<p>`, `<li>`).

* Для самозакрывающихся элементов (например, `<img>`, `<br>`) не используйте косую черту в конце (`<br />` → `<br>`).

## 3. Семантика и доступность (a11y)
### 3.1. Семантические теги

Используйте семантические теги вместо `<div>` и `<span>`, когда это возможно:

    <header>, <footer>, <nav>, <main>, <section>, <article>, <aside> — для разметки структуры страницы.

    <h1>–<h6> — для заголовков (соблюдайте иерархию).

    <button> — для кнопок.

    <a> — для ссылок.

### 3.2. Доступность

* Добавляйте атрибут alt ко всем изображениям (<img>). Для декоративных изображений используйте alt="".

* Используйте ARIA‑атрибуты (aria-label, aria-labelledby и т. д.) для улучшения доступности сложных компонентов.

* Обеспечьте логичный порядок табуляции с помощью атрибута tabindex (только при необходимости).

## 4. Атрибуты
### 4.1. Порядок атрибутов

Рекомендуемый порядок атрибутов для лучшей читаемости:

    class

    id

    name

    src, href

    data-* атрибуты

    Остальные атрибуты

Пример:
```html
<a class="link" id="home-link" href="/" data-action="navigate">Главная</a>
```

### 4.2. Пользовательские атрибуты

Для пользовательских данных используйте атрибуты data-*.

Пример: `<div data-user-id="123">...</div>`
## 5. Комментарии

* Используйте комментарии (<!-- ... -->) для пояснения сложных участков кода или логической группировки блоков.

* Не оставляйте «мёртвый» код в комментариях. Удаляйте его.

Пример:
```html

<!-- Навигация сайта -->
<nav class="main-nav">
  <ul>
    <li><a href="/">Главная</a></li>
    <li><a href="/about">О нас</a></li>
  </ul>
</nav>
```

## 6. Именование классов и идентификаторов

* Используйте стиль kebab‑case (слова через дефис) для имён классов и id.

* Имена должны быть осмысленными и отражать назначение элемента.

* Избегайте слишком коротких или общих имён (box, content).

Хорошо: main-header, user-profile-card, btn-primary.
Плохо: mh, upc, b1.
## 7. Ссылки и пути

* Для внутренних ссылок используйте относительные пути.

* Всегда указывайте протокол (https://) для внешних ссылок.

* Для ссылок, открывающихся в новой вкладке, добавляйте target="_blank" и rel="noopenernerferrer".

Пример:

```html
<a href="/about" class="nav-link">О нас</a>
<a href="https://example.com" target="_blank" rel="noopener noreferrer">Внешний ресурс</a>
```

## 8. Изображения

* Всегда указывайте атрибуты src и alt.

* Для адаптивных изображений используйте <picture> или атрибуты srcset и sizes.

* Оптимизируйте изображения перед загрузкой на сайт (сжатие, правильный формат).

Пример:

```html
<img src="image.jpg"
     alt="Описание изображения"
     srcset="image-480.jpg 480w, image-800.jpg 800w"
     sizes="(max-width: 600px) 480px, 800px">
```

## 9. Лучшие практики
### 9.1. Валидность кода

* Проверяйте HTML‑код на валидность с помощью валидатора W3C ().

### 9.2. Минимизация разметки

* Удаляйте лишние пробелы, табуляции и пустые строки перед деплоем (используйте инструменты сборки).

* Избегайте избыточных div-обёрток.

### 9.3. Производительность

* Подключайте скрипты в конце <body> (или используйте defer/async).

* Минимизируйте количество HTTP‑запросов (объединяйте CSS/JS, используйте спрайты).

Инструменты для проверки стандартов

**Для автоматического контроля соблюдения стандартов используйте следующие инструменты:**

* HTMLHint — линтер для HTML, проверяет синтаксис и стиль.

* W3C Validator — официальный валидатор HTML от W3C.

* Lighthouse (в DevTools Chrome) — аудит производительности, доступности и SEO, включает проверку HTML.

* Prettier — форматировщик кода, поддерживает HTML.

## 10. Заключение

**Соблюдение этих стандартов позволит:**

* создать семантически правильную и доступную разметку;

* улучшить SEO (поисковую оптимизацию);

* ускорить загрузку страниц;

* упростить совместную работу над проектами;

* облегчить поддержку и масштабирование интерфейсов.
