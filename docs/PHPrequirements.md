# Стандарты кодирования для PHP

Эта документация описывает стандарты написания кода на языке PHP, призванные обеспечить единообразие, читаемость и удобство поддержки кода в проектах. В основе лежат рекомендации PSR.

## 1. Базовые соглашения

### 1.1. Пространства имён и структура файлов

* Каждый файл должен содержать либо класс/интерфейс/трей, либо побочные эффекты (например, подключение файлов или вывод). Не смешивайте их.
* Имя файла должно соответствовать имени класса внутри него (PascalCase).
* Пространства имён должны соответствовать структуре каталогов проекта.

**Пример:**
```php
<?php
// Файл: src/Services/UserService.php

namespace App\Services;

class UserService
{
    // ...
}
```

### 1.2. Кодировка файлов

Все файлы PHP должны использовать кодировку **UTF‑8 без BOM**.

## 2. Синтаксис и форматирование

### 2.1. Отступы и пробелы

* Используйте 4 пробела для отступов (не табуляцию).
* Перед открывающей фигурной скобкой `{}` блока — пробел.
* После ключевых слов (`if`, `for`, `while` и т. д.) — пробел.
* Между параметрами в вызовах функций и объявлениях — пробел после запятой.

**Правильно:**
```php
if ($condition) {
    for ($i = 0; $i < 10; $i++) {
        doSomething($arg1, $arg2);
    }
}
```

**Неправильно:**
```php
if($condition){
for($i=0;$i<10;$i++){
doSomething($arg1,$arg2);
}
}
```

### 2.2. Фигурные скобки

* Открывающая скобка `{` для классов и функций — на новой строке.
* Открывающая скобка `{` для управляющих конструкций (`if`, `else`, `for` и т. д.) — на той же строке.
* Закрывающая скобка `}` всегда на новой строке, кроме однострочных конструкций.

### 2.3. Длина строк

* Рекомендуемая максимальная длина строки — 120 символов.
* При превышении — переносите строки, соблюдая читаемость (например, после оператора или запятой).

## 3. Именование

### 3.1. Классы и интерфейсы

* Именование в стиле PascalCase (UpperCamelCase).

**Примеры:** `UserController`, `DatabaseInterface`.

### 3.2. Методы и функции

* Именование в стиле camelCase.

**Примеры:** `getUserById()`, `saveToDatabase()`.

### 3.3. Переменные

* Именование в стиле camelCase.
* Имена должны быть осмысленными и отражать назначение переменной.

**Хорошо:** `$userCount`, `$isLoggedIn`.
**Плохо:** `$uc`, `$flag`.

### 3.4. Константы

* Все буквы — заглавные, слова разделяются подчёркиванием `_`.

**Пример:** `MAX_USERS`, `DEFAULT_TIMEOUT`.

## 4. Комментарии и документация

### 4.1. Однострочные комментарии

Используйте `//` для кратких пояснений *перед* кодом.

```php
// Проверяем, авторизован ли пользователь
if ($user->isAuthenticated()) {
    // ...
}
```

### 4.2. Многострочные комментарии

Используйте `/* ... */` для развёрнутых пояснений или блокировок кода.

### 4.3. PHPDoc

Обязательно документируйте:
* классы;
* методы;
* функции;
* константы;
* свойства.

Используйте теги `@param`, `@return`, `@throws`, `@var` и т. д.

**Пример:**
```php
/**
 * Получает пользователя по его ID.
 *
 * @param int $id ID пользователя
 * @return User|null Объект пользователя или null, если не найден
 * @throws DatabaseException Если произошла ошибка при запросе к БД
 */
public function getUserById(int $id): ?User
{
    // ...
}
```

## 5. Управление зависимостями и импорты

* Используйте `use` для импорта классов в начале файла, после объявления пространства имён.
* Сортируйте импорты в алфавитном порядке.

**Пример:**
```php
<?php

namespace App\Controllers;

use App\Models\User;
use App\Services\UserService;
use Exception;

class UserController
{
    // ...
}
```

## 6. Обработка ошибок и исключений

* Для обработки ошибок используйте исключения (`try-catch`).
* Создавайте собственные классы исключений, наследуя от `Exception` или его подклассов (`RuntimeException` и т. д.).
* В блоках `catch` обрабатывайте только те исключения, которые можете обработать осмысленно.

## 7. Лучшие практики

### 7.1. Типизация

* Везде, где это возможно, используйте строгую типизацию (типы параметров, возвращаемые типы, типы свойств).
* Включайте режим строгой типизации в начале файлов: `declare(strict_types=1);`.

### 7.2. Видимость методов и свойств

* Всегда явно указывайте модификаторы доступа (`public`, `protected`, `private`).

### 7.3. Избегайте глобальных переменных

* Минимизируйте использование глобальных переменных и функций. Предпочитайте внедрение зависимостей (Dependency Injection).

## Инструменты для проверки стандартов

Для автоматического контроля соблюдения стандартов используйте следующие инструменты:

* **PHP_CodeSniffer** — проверяет код на соответствие стандартам (в т. ч. PSR).
* **PHPStan** / **Psalm** — статические анализаторы кода, выявляющие потенциальные ошибки и проблемы с типизацией.
* **PHP CS Fixer** — автоматически исправляет код в соответствии с заданными правилами.

## Заключение

Соблюдение этих стандартов позволит:
* упростить совместную работу над проектами;
* ускорить процесс ревью кода;
* снизить количество ошибок из‑за непоследовательности;
* облегчить поддержку и масштабирование приложений.

Рекомендуется интегрировать инструменты проверки кода в CI/CD‑пайплайн для обеспечения соблюдения стандартов на постоянной основе.
